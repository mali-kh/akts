# Measurements - 2026-09-01

Host: Lambda A100 instance, AMD EPYC 7J13 (30 vCPU, KVM guest), 216 GB RAM,
NVIDIA A100-SXM4-40GB (driver 580.173.02), Ubuntu 24.04.2,
kernel `6.14.0-27-generic`, BTF present, `sched_ext` compiled in and `disabled`.

All measurements for this work were taken on this host.

Load-time only, as before; `sched_ext` state read `disabled` before and after.

## Benchmark 1: actuation latency

| Arm | p50 | p99 | mean |
|---|---|---|---|
| AKTS slot swap (`bpf_map_update_elem`) | **920 ns** | 950 ns | 931 ns |
| Baseline A: `/proc/sys` write | **1110 ns** | 1131 ns | 1123 ns |

Neither arm is meaningfully faster than the other; both are a single syscall.
Parity is the intended result: AKTS retains knob-tuning actuation cost while
gaining the ability to switch whole policies.

## Environment notes

- Lambda's Ubuntu 22.04 and "Lambda Stack" images ship kernels below 6.12 and
  pin the NVIDIA driver plus a Mellanox OFED DKMS stack to them, so `sched_ext`
  is not reachable without a high-risk kernel replacement. Plain Ubuntu 24.04
  boots stock 6.8 with an empty DKMS state; installing
  `linux-image-6.14.0-27-generic` and *then* the NVIDIA driver gives a clean
  build against the new kernel.
- `nouveau` is not blacklisted by default on the plain image and will claim the
  GPU at boot, leaving `nvidia-smi` unable to talk to a correctly loaded driver.
- No `linux-tools` package exists for 6.14.0-27, so Ubuntu's `bpftool` wrapper
  fails; a versioned binary from another kernel dumps BTF correctly.
